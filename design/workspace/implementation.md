# Implementing the LoopCAT redesign

[Interactive design prototype](index.html) · [Design brief and function map](design.md)

The production redesign follows the project-to-editor journey and extends the same navigation, controls and status patterns to resources, teaching, reporting and delivery. The table records the implementation sequence and the tasks used to check it. See the [production verification record](verification.md) for results, measurements and remaining release checks.

## Delivery sequence

The product owner waived the user pilot for this revision. Validation uses reproducible project, translation, review, resource management and teaching workflows. Timing figures in the verification record measure the application. Human task completion and time savings have not been measured.

## Engineering constraints

- **CSS and distribution.** The main entry loads `styles.css` and `liquid-glass/styles.css` ahead of semantic tokens and feature styles. Use the existing compatibility aliases while migrating. Check computed styles on the real screens where legacy selectors have higher specificity. List additional shipped assets in `config/production-assets.js` and the desktop `package.json` file allowlist. Bump `STATIC_ASSET_REVISION` in `service-worker.js` for a cached UI change and test an offline reload after upgrading. Bundle any new icon or font locally.
- **Window and preference state.** Preserve existing `system`/`light`/`dark`, `balanced`/`compact`, collection view, inspector visibility and width values. `src/features/workspace/workspace-layout-controller.js` starts the inspector at 320 px and supports 280–420 px. At constrained widths, return focus to the inspector opener when dismissed. Resource editors already switch to a full-width form below 900 CSS px and restore the library query, selection and scroll on return.
- **Language and input.** Edit the English source and locale JSON catalogs, then extract/sync, translate, validate and compile with the existing `pnpm i18n:*` scripts. Test English, Turkish, Catalan, Spanish and Arabic. Mirror navigation and resize direction in Arabic. Resolve each bilingual cell’s text direction from its content/language, isolate protected tag labels and keep IME and AltGraph input working. Check top-level and secondary windows after changing theme or language.

## Acceptance measures

The English design prototype was checked in headless Chrome, opening the HTML directly from disk. At 1366 × 768 the combined source and target cells occupied 62.8% of the full viewport with the inspector open and 86.5% with it closed. The editor header and toolbar measured 145.4px from the start of the editor content to the grid heading. The global breadcrumb bar and the column heading add to the distance from the top of the window to the first row. These are sample-layout measurements. Compare production builds using the same fixture and denominator.

The original prototype was checked for horizontal overflow on seven screens at 320, 390, 820, 1024, 1366 and 1440 CSS pixels. Its 38 axe scans reported zero violations. The production results below are documented separately because they cover real storage, commands and translated interfaces.

| Measure | Release criterion |
| --- | --- |
| Space for translation | At 1366 × 768, retain the existing source-plus-target width gates of 55% of workspace with the inspector open and 70% closed. Record the rail width and the source-plus-target share of the **whole viewport** too, so adding navigation cannot hide a loss of reading space. Investigate any decline from the fresh baseline. The September review recorded 61.91% and 85.33% of workspace respectively. At editor widths of at least 1100 px, retain the 150 px maximum height above the grid used by the toolbar test. |
| Keyboard, contrast and reflow | No serious or critical axe findings in `pnpm verify:a11y`. Triage the remaining findings. Check visible focus, dialog return, input labels and reading order with NVDA and VoiceOver. Run `pnpm verify:arabic`, check 200% zoom, narrow reflow, forced colors and reduced motion. Double-check the toolbar, inspector and menus with keyboard only. |
| Responsiveness under load | Run `pnpm verify:exchange-perf` on the existing 10k/100k fixtures. Preserve its paired gates and its 10k P95 budgets of under 100 ms to paint and 2 s to durable save. Measure resource loading separately with `node scripts/verify-resource-workspace.cjs --performance-gate`. The 15 November reference result was 3,375 ms against a 2,000 ms goal. Report the measured change and keep that outstanding performance item visible. |
| Task integrity | Verify resume, keyboard translation, review, resource editing and frozen offline lessons with disposable profiles. Investigate any lost edit, unintended external send or wrong-scope delivery. |

## Release and rollback

Run `pnpm verify:baseline`, `pnpm verify:renderer`, `pnpm i18n:validate` and the feature checks above. Build the actual web artifact using `pnpm dist:web`, then run `pnpm verify:web-artifact` and `pnpm verify:web-smoke`. On each desktop release host, run `pnpm pack` followed by `pnpm verify:desktop-smoke`. Exercise the offline web app and packaged secondary windows with both new and existing profiles. Repeat screen-reader and platform checks on their actual hosts.

Keep presentation changes reviewable by slice and retain the existing storage, package and command contracts. Roll back a failing slice with its matching markup, CSS and bindings. Rebuild the artifact, issue a fresh PWA cache revision, and verify a previously edited project and an existing resource draft reopen correctly. Preserve user preferences and translation data throughout the rollback.
