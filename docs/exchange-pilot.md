# LoopCAT Exchange: independent pilot

Use an unpublished build and disposable projects. A pilot should tell us whether someone unfamiliar with the implementation can use the packs without coaching. Record the build identifier, edition, locale, outcome of each exercise and any point at which the facilitator had to intervene. No project text, provider key or learner rationale is needed in the pilot record.

| Participant | Exercise | What counts as success |
| --- | --- | --- |
| Authoring translator | Use **Create** to write a glossary and one QA rule for a domain you know. Include a real exception. Try the examples, exclude a term you cannot redistribute, and send both exported files to the second translator. | A second person can tell what each pack does, what it licenses, and why the rule flags one sentence but accepts another. Neither translator needs an account. |
| Receiving translator | Disconnect; import and inspect both files. Open two projects but activate only in A. Copy a permitted term into your writable termbase, edit and confirm a translation, then remove the packs. Reopen both projects. | A saw the client’s terms and checks; B did not. A’s accepted target and independent term remain. A fresh device warns before ordinary export and produces an incomplete Passport when the required pack is absent. |
| Second instructor and learner | Adapt the sample lesson to a different passage. Export it and run it with one learner offline. Pause and restart before reveal. Have the learner decline study sharing, then delete a response of their choice. | The candidate order survives restart. The learner cannot identify candidates through visible or accessible labels before committing, can decline sharing, and understands that deleting a response and uninstalling a lesson are independent. |
| Catalog maintainer and reviewer | In a **private test catalog**, review a listing against its content, publish its digest, issue a correction as a new version, and withdraw the first version. Check a previously disconnected recipient before and after importing the new snapshot. | A reviewer can trace both artifacts and the advisory to the signing identity. An update does not silently switch a live project; a withdrawal affects only the reviewed bytes after a trusted update. |

Note separately whether each exercise was **completed independently**, **completed with assistance**, **not completed**, or **not run**. A demonstration by the implementer and an automated test do not count as independent reuse. Screen-reader and keyboard pilots should include both a right-to-left locale and a setting with bilingual content of different directions. Invite voluntary feedback; the editor need not collect usage data.

Performance, security and publishing have separate gates. Keep [the full performance report](loopcat-exchange.md#verification-and-release-decision), an independent signing-process review and edition-specific executable-extension qualification separate from usability observations. A successful offline pilot does not authorize enrolling a public signing root or enabling guest code.
