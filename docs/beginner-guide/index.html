Welcome

Translation tools, without the fog

LoopCAT is a computer-assisted translation workspace for translators, post-editors, reviewers, students, and educators. It works offline for the core workflow, keeps project data on your device by default, and adds translation memory, terminology, QA, review, and optional AI when you need them.

The beginner promise. Start with one project and one source file. You do not need to configure AI or understand every panel before translating.

The whole workflow

  1. CreateName the project and choose the exact language pair.
  2. ImportBring in a source file; LoopCAT converts translatable content into segments.
  3. TranslateWork in the Source / Target grid with optional TM and terminology help.
  4. CheckConfirm segments, run QA, and review flagged risks.
  5. DeliverExport the selected target file and save a portable project package.

Step 1

Install LoopCAT

LoopCAT is currently distributed as an unsigned development preview. For most beginners on Windows, the installer is the clearest choice.

EditionBest forWhat to do
Windows installerRegular use on one PCDownload the Setup ZIP, extract it, and run the installer.
Windows portableTrying LoopCAT or carrying it between foldersDownload the Portable ZIP, extract it, and run the EXE. No installation is required.
LoopCAT WebBrowser use or local hostingDownload and extract the Web ZIP. Open index.html, or serve the folder over HTTP/HTTPS for installable offline PWA behavior.

Install on Windows

  1. Open the official downloads folderUse its versioned application packages, not GitHub's automatic Source code ZIP.
  2. Choose a packagePick Setup for a normal installation or Portable for a no-install copy.
  3. Extract the ZIPRight-click it, choose Extract All, then open the extracted folder.
  4. Verify the checksumCompare the ZIP's SHA-256 hash with the same version's checksum list.
  5. Run LoopCATOpen the Setup EXE or Portable EXE.
About SmartScreen. The current Windows preview is unsigned, so Windows may show an unknown-publisher warning. LoopCAT does not bypass it. Continue only if you trust the repository and have verified the checksum.

Verify the download in PowerShell

Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\Path\to\LoopCAT.zip'

Compare the full value with the matching filename in the versioned checksum list. A checksum detects a damaged or mismatched download; it is not a publisher signature.

Using LoopCAT Web

  • Opening index.html directly runs the app, but browsers cannot install its service worker from a file:// address.
  • Serve the extracted folder from an HTTP/HTTPS address for installable offline PWA behavior.
  • Export project packages regularly. Clearing browser data can remove locally stored projects.

Step 2

Start your first project

The five-minute route. New project → choose languages → Create → Import files → open the file → type a target → Ctrl/Cmd + Enter → Run QA → Export.

Create the project

  1. Select New projectIt appears in the upper-right of the Projects view.
  2. Enter a project nameUse something recognizable, such as Client – Product – Month.
  3. Add Creator and DomainOptional, but useful for professional and academic records.
  4. Choose the exact language pairThis controls compatible TM, termbase, spellcheck, package, and AI matching.
  5. Open Storage and resources if usefulOptionally choose a visible package folder, link resources, create a main TM/termbase, or configure AI.
  6. Select CreateYou will land on the project dashboard.

Project name

Website refresh – English to Turkish

Domain

Marketing, legal, medical, technical, academic, etc.

Main TM

Create one if confirmed segments should become reusable matches.

Termbase

Optional at first; valuable for approved names and terminology.

Language-pair tip. A broad language code and a locale-specific code can represent different contexts. Choose carefully before linking resources.

Import a source file

  1. Select Import filesChoose one or more files from the project dashboard.
  2. Wait for processingLoopCAT extracts translatable content and builds segment rows.
  3. Review the file cardCheck the filename, word count, segment count, and progress.
  4. Open the fileThe editor displays the selected document; use Back to files to return.

Common beginner-friendly formats include DOCX, XLIFF, HTML, Markdown, CSV/TSV, JSON, XML, SRT/VTT, and TXT. Many additional Office, OpenDocument, publishing, localization, resource, and subtitle formats are supported; perfect reconstruction of every complex structure is not claimed.

Step 3

Meet the translation editor

Every row is a segment. Read the Source, work in the Target, then use Status and the Inspector to keep track of progress and context.

Source

The text to translate, including protected tag chips.

Target

Your translation. Type, paste, or insert a suggestion.

Status

Empty, draft, confirmed, plus independent review states.

Inspector

Matches, Quality, Review, AI, and Info for the active segment.

Your everyday loop

  1. Select a segmentClick its Target field; the Inspector updates for that row.
  2. Translate or insert a suggestionPress Tab when Quick Insert results are available.
  3. Preserve protected tagsF8 inserts the next missing protected tag at the caret.
  4. ConfirmPress Ctrl/Cmd + Enter. With a main TM, the confirmed pair can become reusable.
  5. Move forwardPress Alt/Option + Enter for the next unconfirmed segment.
Saving. Target edits autosave locally. Watch the save status at the top. Saved is useful feedback, but a portable project package is still your durable backup.

Step 4

The features you will use most

Translation memory matches

A TM stores source–target pairs so previous work can be suggested again. Exact matches are strong starting points; fuzzy matches are similar and normally need editing. Use F4 or Ctrl/Cmd + Shift + K for concordance.

Quick Insert

Press Tab in a Target field when suggestions exist. The picker can show up to four TM matches, three approved terms, and two saved AI suggestions. Use arrows or Tab to move, 1–9 to choose, Enter to apply, and Escape to close.

Termbases

A termbase records approved or forbidden terminology. Approved terms can be inserted; forbidden terms are excluded from Quick Insert and may block delivery if they appear in the target. Manage shared TM and TB resources from Resources.

Protected tags

Formatting codes, variables, and inline markup appear as protected chips. Keep every required chip and place it around the correct translated text. LoopCAT prevents confirmation when required placeholders are missing.

Search, filters, and Focus mode

Use Ctrl/Cmd + F to search source, target, or both. Filter by document, segment status, review state, or AI status. Workflow presets combine common filters. Focus mode gives the grid more room.

Step 5

Quality and review

Run QA checks

Choose Segment tools → Run QA checks or press Shift + F9. Checks cover empty targets, missing tags, copied source, number mismatches, punctuation mismatches, and termbase usage.

  1. Run QADo it after a meaningful translation batch and before export.
  2. Open QualityRead each issue's severity and fix hint.
  3. Jump and correctFix the target or confirm that the difference is intentional.
  4. Run QA againConfirm which issues remain.
QA is a safety net. A clean result does not prove meaning, tone, or style. Read the translation; use QA for repeatable mechanical risks.

Review tools

Needs review

Flags a segment for another pass.

Reviewed

Records that the review pass is complete.

Blocked

Marks an unresolved question or dependency.

Comments & revisions

Capture decisions and inspect recent target changes.

Optional Local AI

The core workflow does not require AI. Most AI editing commands save reviewable suggestions rather than overwriting the target. AI pretranslation writes into eligible targets and marks them as needing review. Hosted providers require explicit configuration and source-sharing confirmation.

Step 6

Export, deliver, and back up

  1. Select the correct documentIn a multi-file project, make sure the intended file is active.
  2. Run QA and resolve blockersMissing tags, forbidden terms, unsafe output, or missing reconstruction data can block delivery.
  3. Open ExportChoose Target DOCX, Export current file, XLIFF, Target TXT, Bilingual DOCX, or a report.
  4. Review incomplete-work warningsCancel if the project is not ready.
  5. Open the exported fileCheck layout, formatting, links, numbers, and language details in its final application.

Choose the right output

Target DOCX / current file

Reconstructs the selected imported file with translated content.

XLIFF 1.2 / 2.2

Creates bilingual interchange or handoff content.

Bilingual DOCX

Useful for review with statuses, notes, comments, and QA summaries.

Reports / Quality Passport

Creates offline project and quality evidence.

A good backup habit. At the end of a work session, export both the target file and a portable project package to a separate folder or backed-up drive. The target protects the result; the package protects the editable CAT state.

Before you deliver

  • The intended document is selected.
  • Required segments are translated and confirmed.
  • Protected tags and placeholders are correctly placed.
  • Names, numbers, dates, punctuation, and approved terms are checked.
  • QA has been rerun after final corrections.
  • The exported file opens and looks correct.
  • A portable project package is saved somewhere safe.

Troubleshooting

No suggestions

Check that the TM/termbase is linked and uses the project language pair.

Cannot confirm

Look for missing protected tags; press F8.

Export blocked

Read the validation message, run QA, resolve blockers, and retry.

Web projects missing

Restore a browser backup or import a saved project package.
