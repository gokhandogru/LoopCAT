# LoopCAT 0.0.4-dev.20260914.5

Opening a project no longer triggers exhaustive TM comparison on the interface thread. The file view calculates TM analysis in a separate worker, reads only linked memories, and cancels the calculation when the translator opens the editor. Analysis cannot queue ahead of active-segment TM matches or QA.

Startup prepares segment and activity records for up to three recently accessed or created projects. This disposable memory cache checks the database generation and restore epoch before use, and discards entries after writes. Project ownership and authoritative record checks remain in place. Speculative loading skips projects over 5,000 segments and retains at most about 2 MiB of serialized content per project; larger projects load on demand.

Workspace-folder reconnection reads manifest metadata without opening and validating every legacy project package. Missing manifests are not rebuilt automatically during startup. Explicit package listing, import, saving with a missing manifest, and health/recovery operations still perform their required validation.

Validation: 1,509 unit tests, including cache freshness across commits/restores, background-analysis score parity, and cancellation that leaves active TM lookup running. Renderer lint, formatting, TypeScript, and release-contract checks pass. A copied Windows test workspace opened the editor in approximately 0.4 seconds; this is a diagnostic sample, not a guarantee for every project or machine.

These shared renderer changes apply to desktop and web. The GitHub release workflow builds the static web ZIP, Windows installer and portable application, macOS DMG and ZIP, and Linux AppImage and DEB from one committed repository revision. The published desktop files remain unsigned development previews; signing, notarization, and broader clean-machine qualification are still required before a stable production release.
