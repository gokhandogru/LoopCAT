# LoopCAT 0.0.4-dev.20260914 — startup fixes

This development build addresses slow or apparently frozen startup when an installed desktop app opens a previous LoopCAT test profile. A newly installed executable can reuse existing per-user application data.

- Resource migration processes translation-memory entries and terms in bounded batches within one atomic transaction. It no longer loads and rewrites the complete derived token indexes during database opening. Existing search paths rebuild dirty indexes before use.
- Database upgrades display progress. Unrelated Saved notices cannot hide initialization, and initialization completion does not clear a separate persistence error.
- New Project displays a loading label, prevents duplicate pending opens, and allows retry after a failed database read. Its failure message remains visible.
- Desktop saving and close checks wait for an in-progress database open or upgrade.
- The packaged desktop smoke check clicks New Project and verifies that its dialog opens before testing creation, saving, imports, exports, and backup.

The source fixes are shared by Windows, macOS, Linux, and web builds. Windows is the native verification target for this change. Existing published downloads are not updated by this local build; no new macOS or Linux qualification is claimed.

Application version: `0.0.4-dev.20260914`. Database schema 8, project-package schema 6, and backup schema 7 are unchanged.
